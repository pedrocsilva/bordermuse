# Windows feature parity

The first Windows alpha targets the complete macOS `0.1.0-alpha.2` feature set.
The Windows app is development work; source/CI artifacts do not establish release
readiness. No macOS geometry or rendering behavior changes as part of this port.

| Capability | Windows implementation | Release gate |
| --- | --- | --- |
| Exact canvas, all ratios, thickness 0–50, Original | Independent .NET geometry package | All 20 canonical cases and arithmetic boundary/error checks |
| JPEG/PNG/single-image TIFF, orientations, 8/16-bit | Separate WIC adapter | Native synthetic format/orientation/depth tests plus real photos |
| White fill, optional content reduction, JPEG quality | Windows renderer | Dimensions, filter quality and white/transparent compositing checks |
| Color profiles and metadata keep/remove | WIC color contexts, cloned metadata and bounded PNG EXIF/XMP normalization | sRGB/P3 and camera/GPS/XMP round trips; no silent unsupported HDR conversion |
| Preview uses export geometry | Native WinUI canvas and shared geometry call | Preview/export agreement at multiple DPI settings |
| Photo import, removal, selection, deduplication | Portable session and native filmstrip | Core tests plus actual file panels, keyboard and drag/drop |
| Versioned presets | Shared JSON schema and portable store | Persistence, invalid documents, failed writes, cross-platform settings |
| Batch progress/cancel, partial errors/retry | Portable serial exporter and Windows dialogs | Cancellation during encoding, retry, denied access and quit cleanup |
| Original/existing output protection | Version check, temporary file, non-overwriting move | Hash/overwrite/race checks |
| File-manager opening/reveal | Activation routing and Explorer selection | Open With and multi-file reveal on an installed copy |
| Accessibility and light/dark/minimum size | Native controls, labels and theme changes | Narrator, full keyboard traversal, high contrast, resizing and DPI review |
| Developer CLI | `apps/cli-dotnet`, same renderer | Matching arguments and native export tests |
| Distribution | Self-contained x64 development artifact | Clean-machine installation, ARM64 decision, signing/security-prompt documentation |

`packages/geometry-dotnet` depends only on .NET. `packages/core-dotnet` owns
settings, presets and batch/session behavior without Windows references.
`packages/imaging-windows` uses the managed Windows Imaging Component APIs
exposed by the Windows desktop framework. `apps/windows` supplies WinUI controls,
file panels, activation and Explorer integration. macOS remains native SwiftUI.

The measured JSON corpus is linked into the .NET tests unchanged. All ports use
the same contract identifier. Pixel preparation/encoding have separate checks:
geometry agreement does not promise identical filters or encoded files.

Portable tests can run on macOS/Linux. Native imaging tests and complete WinUI
packaging must run on Windows; `.github/workflows/windows.yml` does both and
uploads a development app. Manual gates above remain open until evidence exists.

## Automated evidence

[Windows run 40172130371](https://github.com/pedrocsilva/bordermuse/actions/runs/40172130371)
passed on revision `4dcca1e` on October 25, 2026:

- Eight portable tests, including all 20 measured geometry cases, session/preset
  behavior and bounded PNG EXIF parsing, CRCs and metadata chunk rewriting.
- Seventeen native codec tests covering all eight orientations, supported formats,
  precision, metadata policy, output protection, resizing and cancellation. Fine
  checkerboard reduction checks cover 8-bit and true 16-bit images.
- Ten shared sRGB/P3 round trips, generated by ImageIO and consumed on Windows,
  checking rotation, ICC profiles, true 16-bit samples and opaque XMP preservation
  plus normalized orientation/dimension tags.
- The published workspace exercised import/deduplication, preset restoration,
  Original/2048/Custom sizing, invalid drafts, secondary-instance activation,
  partial failure/retry and cancellation during a large batch. Both system close
  and menu quit reached the shared confirmation path: Keep Working preserved the
  batch; Stop and Quit canceled and awaited cleanup before the window closed.
  Completed exports survived cancellation, temporary files were removed, and
  originals/existing outputs remained intact. Light/dark/minimum-size captures
  accompany the run.
- A live system contrast-theme switch updated the workspace, stage and validation
  brushes to the system window/text colors, preserved the photo's white border,
  and restored the previous setting. Customized palettes and broader DPI review
  still require hands-on checks.
- With external .NET lookup disabled, the app loaded its bundled .NET and WinUI
  modules. Package metadata identifies its source revision and bundled runtimes;
  per-file checksums were verified after the native launch.

[Public photo run 40129466203](https://github.com/pedrocsilva/bordermuse/actions/runs/40129466203)
passed at renderer revision `064149f`. Three hash-pinned public JPEGs were exported by both
renderers at original and 2048-pixel photo sizes, with metadata kept and removed.
Dimensions, orientation, ICC/selected camera metadata, white borders and original
hashes passed. Full-size mean RGB differences were 0.86–1.47 levels out of 255;
the large photo reduced to 2048 measured 3.00 levels and 34.92 dB PSNR. Windows
uses scale-aware Lanczos-3 reduction. These samples do not establish calibrated
display accuracy or broad camera/editor coverage.

These results cover the named revision. Narrator, complete keyboard traversal,
actual file panels and cross-window drag/drop, customized contrast themes/DPI,
installed Explorer integration and independent installation remain release gates.

## Hands-on acceptance

Use a downloaded development artifact, not a source-tree executable. Record its
`BorderMuse-build.json` source commit, Windows version, display scale and result.

1. On a PC without a .NET SDK, extract the complete folder and launch the app.
   Import JPEG, PNG and single-image TIFF through Add Photos and Explorer
   drag/drop. Check multiple selection, duplicates and non-ASCII filenames.
2. Complete import, photo navigation, preset save/restore and export using only
   the keyboard. With Narrator enabled, check control names/values, selected-photo
   announcements, validation and export progress. Confirm focus returns after
   dialogs and errors.
3. At 100%, 150% and 200% display scaling, review the minimum window with Export
   Options expanded and an invalid value. Check scrolling, focus visibility and
   readable errors. Try the built-in contrast themes and a customized palette.
4. Export a varied photo batch at Original, 2048 and Custom sizes, keeping and
   removing metadata. Compare color and detail in the source editor and an image
   viewer; verify originals and existing outputs stay intact. Check denied folder
   access, retry and both quit-dialog choices during export.
5. Test Open With/command-line file opening and reveal of multiple exports in
   Explorer from the downloaded app. Repeat launch/export on an independent PC.

CI covers only its named automated subset. A passing native smoke report does
not mark these complete keyboard, assistive-technology or installation checks done.
